# Agent memory: evidence of the proposal → decision → memory flow

Generated by `python scripts/memory_evidence.py` from a real run of the agent's graph, decision classifier, forbidden-content policy, memory store and audit log (an in-memory database). Design and policy: [memory-design.md](memory-design.md).

> **What is real and what is not.** No live language model was available to this run, so the model's replies (the answer and its `memory_proposal` field) are **scripted by hand**, in exactly the JSON format the real model is asked to produce. Everything that happens *around* the model is the real code: the gates on the proposal, the policy, the classification of the user's reply, the store, the audit log and the prompt that the next conversation receives. The text of those prompts below is the real prompt.

## Also: a change of topic is a discard, never an approval

**Conversation `conv-C1`.**

**valentina:** The cosmetics client always wants their monthly report with the returns breakdown first, before shipment volume.

**Agent:**

> Noted.
>
> ---
> Want me to remember this for next time?
> > The cosmetics client wants its monthly report with the returns breakdown first, before shipment volume.
> Reply yes to save it, no to skip it, or tell me how to change it.

*trace: receive_question → plan_sources → retrieve_context → generate → propose_memory*

**valentina:** What is the SLA for express?

**Agent:**

> I didn't save the earlier suggestion, since you moved on to something else.
>
> Express shipping takes 24 to 48 hours.

*trace: receive_question → resolve_memory → plan_sources → retrieve_context → generate*

The proposal was discarded (`discarded_topic_change`) and the new question was still answered. A message such as "maybe", "ok" or "sounds good" is discarded too (`discarded_unclear`): approval is never assumed.
